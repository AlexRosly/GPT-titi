# Патч 39 — OCR ділянок зі змішаними системами письма

База: 63a0ca8da0362726ecad765723dbb775685c1f6a (патч 38).
Нових npm-залежностей, зовнішнього OCR API чи викликів мовної моделі немає.
Фронт змінювати не потрібно: Saved extraction вже відображає збережений текст.

## Поведінка

Увімкнення: OCR_REGIONS_ENABLED=true разом з OCR_LANGUAGES=auto.
За замовчуванням додатковий прохід вимкнений: спочатку перевірити тести на сервері.
Ручний OCR_LANGUAGES зберігає попередню поведінку.

Після первинного OCR збираємо його рядки за TSV, зберігаючи порядок слів, включно з RTL.
Перевіряємо максимум 12 рядків; спочатку — рядки з нижчою впевненістю.
Короткі рядки (<10 розпізнаних букв) пропускаються. Це вибіркова перевірка, не повне
виявлення всіх мов: ділянки, повністю пропущені первинним OCR, тут не відновлюються.
OSD визначає систему письма на зображенні ділянки. Якщо потрібна інша модель,
повторно читаємо саме цю ділянку. Використовується чинний набір 33 моделей письма.
Низька впевненість OSD допускає лише кандидата: повторне читання повинно мати
впевненість >=85, щонайменше на 5 вище первинного рядка, і >=50% букв відповідної
системи письма. Для впевненішого OSD поріг повторного читання >=70.
Ці пороги — евристики, не ймовірність правильності.

Первинний текст не замінюємо. Додаємо OCR REGION ALTERNATIVES: original, alternative,
номер рядка в первинному OCR, координати, script/models, scriptDetectionUncertain,
numericAgreement. Розбіжності цифр явно позначаємо; дати та суми не виправляємо.
Альтернативи виводяться у первинному порядку рядків. Модель отримує інструкцію
показувати обидва релевантні читання, не робити прихований вибір.

## Межі й діагностика

- До 8 секунд додаткового бюджету на worker: для фонового PDF це одна сторінка;
  для старого синхронного багатосторінкового виклику — весь документ.
- OSD ділянки до 1 секунди, повторний OCR до 2 секунд; спільний ліміт worker 55 секунд
  не збільшується. Залишається резерв для завершення та наступних сторінок.
- До 8 KiB приміток на сторінку; чинні ліміти тексту, пам’яті й квоти збережені.
- Збій додаткового процесу зберігає успішний первинний OCR і дає CHECK INCOMPLETE.
- Приватні detections[].regions містять лічильники, витрачений час, результати OSD
  за номерами рядків і причини неповної перевірки; текст документів у серверний лог не пишемо.

## Кеш і продовження

Новий кеш має regionProfile=regions-1. Старий кеш залишається доступним для читання
та вже прийнятих запитів. Після увімкнення режиму наступна підготовка старого файла
оновлює його один раз без повторного завантаження; квота коригується різницею байтів.
F5/Cancel/перезапуск із незмінним профілем використовують готові сторінки.
Зміна профілю під час незавершеної підготовки робить старі checkpoints несумісними:
підготовка почнеться заново. Тому перемикайте режим після завершення активних завдань.
Вимкнення не видаляє вже збережені альтернативи й не переписує історію.

## Алексу: застосування

На актуальній гілці бека з патчем 38, без конфліктних локальних правок:

```bash
git apply --check /path/to/patch39.patch
git apply /path/to/patch39.patch
npm run ocr:check
OCR_REGIONS_ENABLED=false npm run test:files
npm run test:ocr:regions
# Тільки окрема тестова Mongo replica-set БД gptiti_files_test_*, НЕ production:
OCR_REGIONS_ENABLED=false npm run test:files:integration
OCR_REGIONS_ENABLED=true node --test test/files/ocrInternational.test.js test/files/ocrMixedScripts.test.js
```

FILES_TEST_MONGO_URI має посилатися на окрему тестову БД: інтеграційні тести видаляють її.
Tesseract/Poppler та script-моделі — ті самі, що для чинного OCR; OCR_TESSDATA_DIR за
потреби залишити як на сервері. npm ci/збирання Docker для цього патча не потрібні.

Після успішних тестів зберегти в конфігурації сервера:

```dotenv
OCR_LANGUAGES=auto
OCR_REGIONS_ENABLED=true
```

```bash
OCR_REGIONS_ENABLED=true OCR_LANGUAGES=auto pm2 restart gpt-titi-back --update-env
```

Перевірити саме live process, а не лише .env:

```bash
ocr_pid=$(pm2 pid gpt-titi-back)
tr '\0' '\n' < /proc/$ocr_pid/environ | grep -E '^OCR_(REGIONS_ENABLED|LANGUAGES)='
```

Для швидкого вимкнення: зберегти OCR_REGIONS_ENABLED=false у конфігурації та
OCR_REGIONS_ENABLED=false pm2 restart gpt-titi-back --update-env.

## Коротка перевірка через інтерфейс

1. Завантажити QA/mixed-2-pages.pdf з архіву; попросити показати текст обох сторінок.
2. Відкрити Saved extraction. Первинний текст може лишатися спотвореним — нижче
   кожної сторінки мають бути явно позначені OCR REGION ALTERNATIVES.
3. Сторінка 1: шукати альтернативи Cyrillic, Greek, Hebrew, Arabic.
   Сторінка 2: Devanagari, Han, Japanese, Korean. Це перевірка абеток/контрольних слів,
   не підтвердження безпомилковості кожного символу.
4. Перевірити 02.11.2026, 11, 137,50 та TEST-01/02 у первинному тексті. У східноазійських
   рядках первинний OCR спотворює цифри; numericAgreement=false має це явно показати.
5. F5: Saved extraction залишається тим самим; готовий файл не запускає новий OCR.
6. Для довшого PDF повторити F5/Continue: готові сторінки не повторюються. Це також
   перевірено автоматизованим інтеграційним тестом з перериванням між сторінками.

## Що ще не вирішено

Не гарантуємо точність усіх мов/шрифтів, рукопису, вертикального письма, таблиць або
кожної короткої вставки. Залишаються ґ/г, апострофи, пробіли в CJK та окремі слова.
Повністю пропущені первинним OCR ділянки потребують незалежного визначення областей
тексту — це окремий наступний крок. Високий confidence не є доказом правильності.
Не підвищувати ліміти й не робити автоматичних замін первинного тексту заради красивої відповіді.
