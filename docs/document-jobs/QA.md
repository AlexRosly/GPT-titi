## Наскрізні сценарії з реальною базою

1. 10 000 рядків, збій після 1 500 збережених рядків, конкурентний запуск двох воркерів, продовження без повторного множення, один готовий файл і одне списання.
2. Cancel без активного chat worker: записаний прапорець зупиняє роботу, оригінал лишається, нова копія не видається, відомі витрати моделі враховуються один раз.
3. Видалення джерела після збереженої порції: проміжні частини прибираються, їхня квота звільняється.
4. Responses API: збережена фонова робота, відновлення status/F5, завершення без додаткового виклику моделі.
5. Прострочена оренда: старий воркер не може записати checkpoint; новий завершує роботу.
6. Вичерпана квота: транзакція порції відкочується, часткового файлу немає, використання моделі не втрачається.
7. Фактичний **SIGKILL дочірнього процесу** після 1 000 збережених рядків: після закінчення оренди новий воркер завершує всі 10 000. У тесті час оренди прискорюється записом минулого `leaseUntil`, а не очікуванням 90 секунд.

Локальне середовище: Node 24.22.1, MongoDB 7.0.16, одноразова replica-set база. Runtime-вимога репозиторію Node >=22.13.0 не змінена. Нових npm-залежностей немає.

OpenAI у цих тестах замінено відповідями на межі SDK. Файли, парсер, worker threads, Mongo-транзакції, контрольні точки, V2 commit, квоти й billing ledger справжні. Це перевіряє виконання відомого плану та облік, але не доводить стабільний вибір інструмента реальною моделлю. Перед увімкненням для всіх потрібен live acceptance у GPTiti з кількома новими чатами.

Нова фоновість стосується адаптера XLSX. Ця перевірка не охоплює 10 000 сторінок PDF/DOCX, серверний перерахунок Excel-формул, візуальну перевірку в Microsoft Excel або необмежені розміри файлів. Повні межі й порядок розгортання — у README.md.
