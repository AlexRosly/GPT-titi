# Патч 40 — межі ділянок для повторного OCR

Застосовувати поверх патча 39. Нових npm-залежностей або зовнішніх OCR/LLM API немає.
Фронт змінювати не потрібно. Чинні OCR_LANGUAGES=auto та OCR_REGIONS_ENABLED=true зберігаємо.

## Що виправлено

Патч 39 брав рамку рядка з первинного OCR. Якщо він пропускав край або розбивав рядок
на кілька фрагментів, повторне читання отримувало обрізаний фрагмент.

Тепер горизонтальні ділянки визначаються за пікселями зображення: смуги тексту та
проміжки між ними. Широкі проміжки розділяють ділянки, щоб не об'єднувати колонки.
Первинні фрагменти зіставляються з ділянками за геометрією. Неоднозначні рамки,
що можуть належати двом рядкам/колонкам, не об'єднуються примусово.

Повний знайдений рядок повторно читається OCR. Для розірваного рядка тією самою
абеткою теж можливе повторне читання: наприклад, English: та решта речення.
Це повторне читання зображення, а не складання чи виправлення тексту мовною моделлю.

Первинний OCR залишається незмінним. Додаються явно позначені альтернативи:
- sourceLines — номери первинних фрагментів, їхні точні рядки в original розділено \n;
- boundsStatus=pixel-region — рамка отримана з пікселів;
- edgeCoverage.left/right — чи розпізнані слова охопили краї знайденої ділянки;
- recognitionIncomplete=true — принаймні один край міг залишитися непрочитаним;
- numericAgreement — лише збіг послідовностей чисел між двома варіантами.

Жоден із цих прапорців не доводить повної правильності тексту. Наприклад, пропущене
слово всередині рядка перевірка країв не виявляє. Дати/суми/імена здогадками не правимо.

## Обмеження

Аналіз зображення: до 1800 пікселів по довгій стороні, до 3,24 MP, максимум 256
попередніх геометричних ділянок. Розпізнавання використовує початковий растр ділянки.
До 12 ділянок для додаткового OCR; спільний додатковий бюджет 8 секунд, загальний
ліміт worker 55 секунд збережено. Час геометричного аналізу входить у додатковий бюджет.
У фоновому PDF worker обробляє одну сторінку; у старому синхронному режимі бюджет
додаткових проходів спільний для документа. Квоти, розміри, кількість сторінок і billing не збільшуються.

Це евристика для горизонтального друкованого тексту. Рукопис, повороти, вертикальне
письмо, складні таблиці з лініями, фотографії/фон, дуже вузькі колонки чи надто широкі
проміжки між словами можуть не пройти перевірку. Первинний текст зберігається,
неперевірені первинні рядки позначають неповну перевірку. Повністю відсутні в первинному
OCR рядки без жодного зіставленого фрагмента цей патч ще не додає.
Залишаються помилки окремих букв, ґ/г, апострофів, пробілів та слів.

## Кеш

Профіль змінено з regions-1 на regions-2. Після патча старий витяг доступний для
читання, але наступна підготовка оновлює його один раз. Повторне завантаження файла
для оновлення кешу на бекенді не потрібне. F5 сам по собі не запускає оновлення OCR.
У межах regions-2 поновлення використовує готові сторінки без повторного OCR;
це перевірено інтеграційно. Старі незавершені checkpoints regions-1 несумісні з новою
геометрією та будуть перераховані. Перед розгортанням дочекатися завершення активних
OCR-завдань. Історичні відповіді моделі автоматично не переписуються.

## Алексу

З актуальної гілки бека з патчем 39:

```bash
git apply --check /path/to/patch40.patch
git apply /path/to/patch40.patch
npm run ocr:check
OCR_REGIONS_ENABLED=false npm run test:files
npm run test:ocr:regions
# Лише окрема тестова replica-set БД gptiti_files_test_*, НЕ production:
OCR_REGIONS_ENABLED=false npm run test:files:integration
OCR_REGIONS_ENABLED=true node --test test/files/ocrInternational.test.js test/files/ocrMixedScripts.test.js
```

FILES_TEST_MONGO_URI — тільки окрема тестова БД, яку тести можуть видалити.
Нативні залежності та script-моделі такі самі, як у патчі 39. npm ci та Docker build
не потрібні: залежності не змінювалися.

Після успішних тестів:

```bash
OCR_REGIONS_ENABLED=true OCR_LANGUAGES=auto pm2 restart gpt-titi-back --update-env
npm run ocr:check
```

У виводі ocr:check з відповідним середовищем очікуємо `OCR regions: regions-2`.
Перевірити також змінні саме live PM2 процесу, як для патча 39.
Швидке вимкнення додаткового OCR: OCR_REGIONS_ENABLED=false у конфігурації та
перезапуск PM2 з оновленням середовища. Вже збережені альтернативи не видаляються.

## Коротка QA-перевірка

Завантажити QA/GPTiti_OCR40_test_2_pages.pdf у новий чат. Запит:
«Покажи повний збережений OCR обох сторінок разом з альтернативами».
Перевіряти Saved extraction, а не переказ моделі.

1. На обох сторінках лишилися 02.11.2026, Quantity 11, Amount 137,50 та TEST-01/02.
2. На сторінці 2 японська альтернатива має закінчення 確認してください。
   (OCR може вставити пробіли). Корейська має початок 이 문서는 한국어
   (також можливі додаткові пробіли), а не починається із середини речення.
3. Якщо первинний OCR розірвав англійські рядки, перевірити повні речення в
   альтернативах із sourceLines з кількох номерів. Якщо первинний рядок уже цілий,
   додаткова така альтернатива не обов'язкова.
4. Перевірити boundsStatus, edgeCoverage та recognitionIncomplete. Якщо останній true,
   потрібна перевірка оригіналу, а не прийняття урізаного рядка за повний.
5. F5 і повторне відкриття Saved extraction: збережений результат не змінюється.

Первинний текст навмисно може й далі містити розірвані/спотворені рядки. Покращення
потрібно дивитися в позначених альтернативах. Повної безпомилковості не заявляємо.
