# Освобождение места от файлов разработки

Использовать только для данных, которые разрешено удалить. Скрипт по умолчанию ничего не меняет в MongoDB: считает реальные байты `filechunks` и сохраняет JSON-план. Выбираются самые большие целые файлы, пока их суммарный объём не составит не меньше 50% байтов `filechunks`. Это может быть значительно меньше половины количества файлов.

Из корня проекта с настроенной `MONGO_URI` в `.env`:

```sh
npm run db:cleanup:dev-files -- --database=GP-TITI
```

В выводе будут кластер, имя БД, объём до очистки, выбранные файлы и путь к плану `backups/file-cleanup/plan-....json`. `--database` задаёт точную БД, независимо от имени в URI. URI и пароль не выводятся. JSON-план содержит метаданные выбранных файлов, а не резервную копию их содержимого; директория исключена из Git.

Чтобы выбрать другую долю объёма, например 60%:

```sh
npm run db:cleanup:dev-files -- --database=GP-TITI --fraction=0.6
```

Для применения используется конкретный сохранённый план. Сначала завершите активные генерации и задания обработки документов, затем остановите API и связанные фоновые обработчики. Для текущего backend под PM2:

```sh
pm2 stop 1
node scripts/cleanupDevelopmentFiles.js --database=GP-TITI --apply=backups/file-cleanup/ИМЯ_ПЛАНА.json
pm2 restart 1 --update-env
```

Копируйте точную команду применения из вывода preview. Скрипт проверяет кластер/БД, неизменность выбранных файлов, достаточность счётчиков квоты и отсутствие queued/processing turns и queued/running document jobs. Остановка процесса сама по себе не переводит зависший turn в завершённое состояние: при сообщении об активных заданиях сначала разберитесь с ними через обычные механизмы приложения.

Каждый файл удаляется штатным `store.remove` в отдельной транзакции: все chunks файла удаляются вместе, метаданные получают `deleted`, кеши очищаются, подготовка отменяется, пользовательская квота возвращается один раз. Чаты, проекты, пользователи и платёжные данные не удаляются. Ссылки в сообщениях сохраняются, но удалённый файл недоступен во всех чатах, где использовался.

Весь пакет не является одной транзакцией. Если выполнение прервано, уже удалённые файлы остаются удалёнными. Повторите **тот же** `--apply=...`: завершённые файлы будут пропущены без повторного возврата квоты. Новый preview выбирает долю уже оставшегося объёма, поэтому не используйте его для продолжения частично выполненного плана.

Проверка после применения (только чтение):

```sh
node scripts/cleanupDevelopmentFiles.js --database=GP-TITI --verify=backups/file-cleanup/ИМЯ_ПЛАНА.json
```

Ожидается: все выбранные файлы имеют статус `deleted`, `remainingSelectedChunks: 0`, `quotaMismatches: []`. Скрипт также покажет оставшийся фактический объём байтов файлов. Сверка квоты учитывает все `ready` файлы и их `derivedBytes`; выполняйте её без активных фоновых заданий, которые могут временно резервировать дополнительный объём.

Chunks без метаданных или привязанные к уже удалённым файлам выводятся как `unlinkedChunks` и автоматически не удаляются. Это отдельный случай для диагностики. Ошибка Atlas `over your space quota` при применении означает, что даже транзакционное обновление метаданных заблокировано; скрипт не обходит ошибку удалением произвольных chunks.

Проверка логики без подключения к БД:

```sh
node --test test/files/developmentCleanup.test.js
```

После освобождения места повторите файловые интеграционные тесты с отдельной `FILES_TEST_MONGO_URI`, как и раньше. Рабочую `GP-TITI` этим runner не тестировать: runner удаляет свою тестовую БД. Перенос MongoDB на VPS выполняется отдельным этапом после очистки и проверки текущих изменений.

## Выполненная очистка 16.11.2026

По прямому разрешению владельца удалены 63 целых файла разработки из `GP-TITI` в `cluster0.fiacqpy.mongodb.net`. Удалено 241 684 459 байт содержимого из исходных 478 812 525. После очистки осталось 237 128 066 байт, 1082 chunks и 273 файла со статусом `ready`. Проверка подтвердила 63 tombstones, отсутствие chunks у удалённых файлов и отсутствие расхождений квоты. План и отчёт сохранены локально в исключённой из Git директории `backups/file-cleanup/`.

14 тестов логики очистки и контроллеров удаления прошли. Полный файловый integration runner выполнен на отдельной `gptiti_files_test_dev`: 56/62 прошли на Windows, шесть получили `OCR_UNAVAILABLE` из-за явного ограничения `ocrProcess` на Linux. Ошибок квоты Atlas больше не было. Полный результат OCR необходимо подтвердить запуском `npm run test:files:integration` на Ubuntu с той же отдельной тестовой БД.
