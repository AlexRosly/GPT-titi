# GPT-titi Stripe Billing — Frontend/Backend Contract

## 1. Get available packages

GET /gpt-titi/api/billing/prices
Authorization: Bearer ACCESS_TOKEN

Response:

[
  {
    "stripePriceId": "price_1XXXX",
    "label": "Starter — 1 000 tokens",
    "appTokens": 1000,
    "amount": 500,
    "currency": "usd"
  }
]

The frontend renders these values into pricing cards.
Do not hard-code prices or token amounts in the frontend.

## 2. Create Stripe Checkout Session

POST /gpt-titi/api/billing/checkout
Authorization: Bearer ACCESS_TOKEN
Content-Type: application/json

{
  "priceId": "price_1XXXX"
}

The backend validates that this Stripe price exists in the enabled Price catalog,
creates the Stripe Checkout Session and returns:

{
  "url": "https://checkout.stripe.com/..."
}

Frontend redirects the user to `url`.

## 3. Stripe webhook

POST /webhook/stripe

This endpoint is called by Stripe, not by the frontend.
It must receive the raw request body so Stripe's signature can be verified.

On `checkout.session.completed` with `payment_status = paid` the backend:

1. reads `userId` and `priceId` from Stripe session metadata;
2. loads the enabled package from the backend Price catalog;
3. creates the Payment record;
4. adds `appTokens` to the user;
5. updates `totalSpentUsd` for USD payments;
6. safely ignores duplicate delivery of the same Stripe session.

The frontend must never add tokens itself.
The success URL is not proof of payment.

## 4. Refunds

Stripe `charge.refunded` is handled by the backend.

Full refunds:
- mark the Payment as `refunded`;
- subtract the package's `appTokens` from the user;
- never allow the balance below -1000 appTokens;
- safely ignore duplicate refund webhook delivery.

Partial refunds are currently ignored because the Payment model does not contain
partial-refund accounting information.

## 5. Payment history

GET /gpt-titi/api/billing/payments
Authorization: Bearer ACCESS_TOKEN

The frontend can use this endpoint for purchase history.

## 6. Stripe CLI

For local development:

stripe login
stripe listen --forward-to localhost:7000/webhook/stripe

Stripe CLI prints a webhook signing secret:

whsec_********

Put it into `.env` as:

STRIPE_WEBHOOK_SECRET=whsec_********

Do not commit `.env` or Stripe secrets.
